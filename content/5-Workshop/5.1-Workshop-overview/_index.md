## Workshop Overview

**"Manage, Monitor and Operate Microsoft Workload Securely on AWS"**

### Problem Statement

Managing Windows Server fleets on AWS manually is error-prone: inconsistent patch levels, no centralized visibility, and RDP exposed to the Internet all increase security risk and operational overhead.

This workshop solves those problems with fully AWS-native tooling — no third-party software, no open inbound ports.

### What You Will Build

By the end of this workshop you will have:

- A **golden AMI** (Windows Server 2025 + CloudWatch Agent) built and versioned by EC2 Image Builder
- **Two Windows EC2 instances** in a private subnet, managed entirely through SSM — no RDP open to the Internet
- **Systems Manager** managing the fleet by tag: Run Command, State Manager associations, Patch Baseline, Parameter Store
- **CloudWatch** collecting Windows Event Logs and IIS logs, a metric filter counting HTTP 403 errors, an alarm, SNS email notification, and a dashboard
- **AWS Config** rules enforcing approved AMIs and required tags
- **Amazon Inspector** scanning for CVE vulnerabilities

### Key Design Decisions

| Decision | Reason |
|---|---|
| VPC Endpoints instead of NAT Gateway | Cheaper and keeps traffic off the public Internet |
| No inbound RDP/SSH | Access only via Session Manager and Fleet Manager |
| Tag-based targeting in SSM | Scales to any number of instances without listing IDs |
| State Manager associations | Ensures CloudWatch Agent config and SSM Agent updates are applied on schedule, not just once |
| Lifecycle policy on Image Builder | Avoids accumulating stale AMIs and EBS snapshots |
